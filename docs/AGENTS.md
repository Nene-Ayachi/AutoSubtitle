# 文档维护约定

本文件适用于 `docs/` 及其子目录。更新工程时，同时检查相关说明是否仍与代码一致。

## 工程约定

- Windows 和 macOS 共用 `backend/`、`frontend/`；平台差异通过设备探测、推理适配层和平台脚本实现，不维护两份业务代码。
- 共用启动逻辑放 `scripts/common/`；平台脚本分别放 `scripts/windows/`、`scripts/macos/`。`portable/` 子目录是成品模板，不能当作源码启动入口使用。
- 成品统一输出至 `release/`；各平台在对应原生系统构建。发布包、模型、用户媒体、缓存、运行日志和私密配置不提交 Git。
- 默认分别发布 Windows x64 和 macOS arm64 ZIP；不要把源码共用误写成运行时可以跨平台共用。

## 状态与验证记录

- [DONE.md](DONE.md) 记录已完成事项、验证日期和证据；[TODO.md](TODO.md) 记录未完成事项及验收条件。
- 完成待办后，先确认验收结果，再更新两份记录；不能仅因代码已实现就标记原生平台验证完成。
- 严格区分单元测试、模拟包组装、真实成品启动、真实模型推理、干净机器验收和性能测试。
- 历史 Windows 验证不代表目录重构后的当前版本已验证；macOS Metal 探测不代表已完成模型识别。
- 构建命令以 [PORTABLE_BUILD.md](PORTABLE_BUILD.md) 为准，历史验证细节见 [../VALIDATION.md](../VALIDATION.md)。命令默认从仓库根目录运行。
- 未取得 Developer ID 证书并完成 Apple 公证前，不声称已公证；首次信任脚本也不能保证只出现一次系统提示。
- 文档使用中文，路径使用仓库相对路径，不记录个人绝对路径、代理凭据、证书私钥或用户媒体内容。
